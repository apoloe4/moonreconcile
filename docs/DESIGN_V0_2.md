## 对评审意见的调整

1. 申报材料单独成文，明确现有基础、拟新增功能、实施顺序和交付物。
2. 项目定位收敛为集合差异摘要与恢复库。算法核心可独立调用；分区、会话协商和本地 Inventory 是可选便利层，不要求消费者引入数据库或网络框架。
3. 参考成熟库的容量、解码与协议边界，明确 IBLT 的概率失败，补充累计成本评估，不把“有摘要”直接等同于“节省传输”。

## minisketch 参考与算法取舍

参考版本：bitcoin-core/minisketch，commit `a12f5de1c96e21d76f64bc647ae4f65e4fc1b636`，核对日期 2026-10-20。

- [官方 README](https://github.com/bitcoin-core/minisketch/blob/a12f5de1c96e21d76f64bc647ae4f65e4fc1b636/README.md)
- [官方协议建议](https://github.com/bitcoin-core/minisketch/blob/a12f5de1c96e21d76f64bc647ae4f65e4fc1b636/doc/protocoltips.md)
- [MIT 许可证](https://github.com/bitcoin-core/minisketch/blob/a12f5de1c96e21d76f64bc647ae4f65e4fc1b636/LICENSE)

| 设计点 | minisketch 的参考意义 | MoonReconcile 本期选择 |
|---|---|---|
| 核心职责 | 独立的 BCH/PinSketch 摘要与解码库 | 保留 MoonBit IBLT，将应用协商与核心契约分开说明 |
| 参数语义 | 容量 c 以内的差异可恢复，b 位 ID 的摘要占 bc 位 | width 是每个分带的单元数，三个分带；不承诺 d ≤ width 就能恢复 |
| 解码与可靠性 | 超容量和 ID 碰撞需要协议层考虑 | 残留非零则失败；结果再核验指纹，但不宣称无碰撞或抗恶意输入 |
| 集合语义 | 代数更新不能直接当作幂等集合操作 | 核心 insert/erase 由调用方维护有效操作；Inventory 提供精确去重 |
| 协议成本 | 未知差异量、往返与重传影响收益 | 统计实际收发摘要及重试总成本，以预算决定继续或回退 |

保留 IBLT 的理由是复用现有纯 MoonBit 核心，评估可恢复 ID、构建成本与实现复杂度之间的取舍，而不是声称它比 BCH 更紧凑。当前 MRCL 单帧大小为 `68 + 60 × width` 字节，包含元数据；minisketch 原始摘要不含同等元数据，比较时必须分别列出摘要与封装成本。当前不承诺实现 BCH、移植 minisketch 或取得性能优势。如果评估未显示适用区间，应公开负面结果并缩小推荐范围。

## 拟新增模块的契约

以下名称是设计草案，最终以实现及生成 API 文档为准，不是当前可调用接口。

- `SessionLimits`：限制最大轮数、累计收发帧字节、累计 peeling 步数及单轮宽度。字节计数用可检查的宽整数；非法预算和算术溢出返回错误。
- `Session`：固定 scope、双方 epoch、seed 和会话标识。驱动方明确报告已发送帧及已接收帧；接收实际字节也占预算，准备发送下一帧前先检查剩余预算。单端本地重建摘要不算网络传输。
- 结果区分 `Ready`、`NeedWiderSketch` 和 `Fallback(reason)`；停止原因至少包含轮数、字节、工作量限制及快照失效。结构损坏、身份不符等错误单独报告，不解释为普通容量不足。
- 合法重传每次都计入字节；同一帧不重复推进状态或重复应用计划。协议状态独立于 HTTP、WebSocket 和文件 IO。
- 每一轮双方使用同一配置并针对各自冻结快照重建。若任一端版本变化，停止旧会话，由应用建立新会话；本库不解决并发写入冲突。
- `Ready` 需要完整恢复和指纹核验；非密码学指纹不是完整内容正确性的证明。需要强验证的应用必须另外验证对象内容和最终集合承诺。
- 回退结果只携带原因及计量，不隐式联网或拉取全量集合。完整清单交换由应用另行决定和执行，超出该会话摘要预算的部分必须单独统计。

## 逐项验收

| 交付 | 验证方法 | 合格条件 |
|---|---|---|
| 核心契约 | 空集、相同集、单边差异、合法增删、容量不足、配置不符、坏帧测试 | 与精确集合差一致；失败不发布可应用计划；原有测试保持通过 |
| 会话预算 | 刚好达到/超过字节、轮数、工作量上限；重复帧；版本变化 | 发送前拒绝超预算计划；接收超限立即终止；重传记账；状态不被跨快照污染 |
| 双端示例 | 在内存传输适配器中交换真实编码帧 | 可复现首次成功、扩容成功、预算回退，并输出实际双向累计字节 |
| 评估脚本 | 固定输入种子、多组规模和宽度，另列计时重复 | 输出逐次原始记录、汇总恢复率和成本；失败与成功均保留，不挑选成功种子 |
| 独立消费 | 发布后新建另一个 MoonBit 模块安装包并运行示例 | 不依赖源码目录，不依赖 C FFI；四目标 CI 保持通过 |

## 评估矩阵与公平比较

首轮固定矩阵：集合规模 `1,000 / 10,000 / 100,000`，对称差 `0 / 2 / 20 / 200 / 2,000`，两端规模相同且各持有一半差异；IBLT 表宽取 `max(1, ceil(d × r))`，`r = 0.5 / 1 / 2`。对每个组合使用 100 个预先固定并公布的输入种子。另测单边差异和高差异率场景。种子集合用于恢复率统计，计时预热和重复不能冒充独立成功率样本；该矩阵不是生产恢复率保证。

记录 `n / d / width / seed / complete / residual / rounds / sent_bytes / received_bytes / build_time / decode_time`，区分单次核心与会话重试评估。固定规模与固定输入生成方式，记录工具链、运行时、CPU 和计时单位。每个成功结果在计时外与精确集合差对照，不只依赖概率指纹。

基线包括原始 UInt64 清单，以及锁定上述版本的 minisketch 独立驱动程序。比较使用共同可表示的非零 64 位 ID 域；零 ID 的处理另列，不静默丢弃或将 0 与其他值合并。minisketch 恢复对称差后，按本地成员关系标注方向，与本库有向结果按集合等价性核对。分别报告摘要裸字节、元数据封装、重试和全量回退成本；不能以一方裸摘要对比另一方完整协议帧后宣称算法优劣。
